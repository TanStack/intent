## Workflow B — Update existing skills

For a current task, supplied diff, identified code/docs change, or accuracy report, follow [generate-skill](../../generate-skill/SKILL.md). It owns the source checks, questions, incremental edits, no-impact decision, validation, and review handoff for each affected task.

For an explicitly requested full-library audit, first identify candidate skills from the supplied changes and their documented scope. A release number is a reason to investigate, not proof of changed behavior. Use actual source diffs, changelogs, and migration guides; leave missing evidence as uncertainty. Apply the focused procedure to each candidate without redesigning the tree. Keep any requested report in the repository's existing format; no new staleness report or changelog is required merely to update a skill.
